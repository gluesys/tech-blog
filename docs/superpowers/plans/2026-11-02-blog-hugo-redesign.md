# TECH-G Hugo Migration and Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Jekyll TECH-G blog with a Hugo site in the CI-aligned design, migrating all 51 posts losslessly and deploying through GitHub Actions.

**Architecture:** A stdlib Python converter turns `_posts/blog/*.markdown` into Hugo content with URLs, heading IDs, and tags pinned from a snapshot of the live site. Hugo templates (plain CSS, TypeScript bundled by Hugo `js.Build`) render the approved mockup. Pagefind indexes the output. Stdlib Python verifiers compare the build with the live snapshot and fail CI on any unexplained difference.

**Tech Stack:** Hugo extended (pinned), Pagefind standalone binary (pinned), Python 3 stdlib (`unittest`, `html.parser`, `urllib`), TypeScript via Hugo `js.Build`, Deno (only for `deno test` of TypeScript logic), GitHub Actions, GitHub Pages, giscus.

**Spec:** `docs/superpowers/specs/2026-11-02-blog-hugo-redesign-design.md` (mockup reference in `docs/superpowers/specs/2026-11-02-blog-hugo-redesign/`)

## Global Constraints

- No npm, `package.json`, or `node_modules` anywhere in the repo or CI.
- Hugo extended and Pagefind are pinned in `tools/versions.env` with SHA-256 checksums; CI verifies them. Third-party Actions are pinned by commit SHA.
- Helper scripts: Python 3 standard library only; tests use `unittest` (`python3 -m unittest discover -s tools/tests`).
- No runtime JS libraries; fonts self-hosted (Pretendard, Saira) with SIL OFL license files.
- Base branch: `origin/master`. Work branch: `hugo-redesign`. Local commits are free; pushes, PRs, and GitHub setting changes need the owner's explicit approval.
- Repository artifacts (code, comments, commit messages, docs) in English. Site UI copy in Korean, exactly as in spec 8.5.
- Color tokens exactly: `--ci-deep #163CCF`, `--ci-bright #1775FD`, `--ci-gray #6A6E7F`, `--ci-navy #274B6B`, `--ci-cyan #00C3D2`, `--ink #1C2233`, `--line #E3E6EE`, `--soft #F4F6FB`. `#5BCF13` unused.
- Body type 17px desktop / 16.5px phone, line height 1.75, article body max 720px, `word-break: keep-all`.
- The CI symbol is never recolored or reshaped.
- GA4 ID `G-7Y6MG4Q2JR`. Search Console file `googlea2b9a3ab05f01437.html` stays byte-identical.
- Live article root selector: `.post-content`. New article root: `div.prose[data-pagefind-body]`.
- Footnote IDs must be `fn:N` / `fnref:N` (same as live).

## Review Focus

1. A post whose front-matter `date` has a time near midnight: its URL date must be the UTC date the live site used, not a local-time date. Test in Task 3 (`test_url_uses_front_matter_date_utc`).
2. A heading whose text contains inline code, links, emphasis, or HTML entities: snapshot matching must compare rendered text, not raw Markdown. Test in Task 3 (`test_heading_match_with_inline_markup`).
3. Image paths with uppercase extensions (`.PNG`, `.JPG`) or Korean characters: they must resolve on the case-sensitive Pages filesystem exactly as before. Test in Task 2 (`test_img_srcs_decode_preserves_case_and_korean`) and Task 5 verifier.
4. Tags that differ only by punctuation or case (`NVMe-oF`, `NVMe over Fabrics`, `file system`): two canonical tags must never produce the same `/tags/<slug>/`. Test in Task 4 (`test_no_canonical_slug_collisions`).
5. Old tag anchors with URL-encoded Korean hashes (`/tags#%EC%8A%A4%ED%86%A0%EB%A6%AC%EC%A7%80`) and raw ones (`/tags#스토리지`): both must land on the canonical tag page. Test in Task 7 (`tags_redirect_test.ts`).
